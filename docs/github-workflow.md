## Pull Request Process

Each member follows these steps:

1. Clone the repository.
2. Switch to the assigned branch.
3. Complete assigned changes.
4. Commit changes with meaningful messages.
5. Push the branch.
6. Create a Pull Request.
7. Project lead reviews the Pull Request.
8. Pull Request is merged into `main`.

## Commit Message Rules

Good commit messages:

- `Add student management documentation`
- `Improve dashboard navigation`
- `Add result management testing notes`
- `Update feedback module explanation`

Bad commit messages:

- `update`
- `done`
- `final`
- `fix`

## Purpose of GitHub Workflow

This workflow helps to:

- Track individual contribution
- Maintain a stable main branch
- Reduce code conflicts
- Provide clear evidence for SE1020 evaluation
- Support final report and viva presentation
